# BiqBin

**BiqBin** is a parallel branch-and-bound solver for Max-Cut and binary quadratic optimization problems.

It provides a native C solver using MPI, Python bindings through pybind11, and support for Max-Cut, QUBO and general BQP problems.

## Getting started

From the repository root, follow the [installation guide](INSTALLATION.md)
to install native dependencies and activate a Python environment. Then:

```bash
python -m pip install -r requirements.txt
make
export OPENBLAS_NUM_THREADS=1 GOTO_NUM_THREADS=1 OMP_NUM_THREADS=1
mpiexec -n 3 python biqbin_qubo.py \
  tests/qubos/40/kcluster40_025_10_1.json -o qubo_result.json
```

The result is written to `qubo_result.json`. If it already exists, the CLI
chooses a numbered filename; add `--overwrite` to replace it. Keep the same
Python environment active when building and running the solver.

For Max-Cut or constrained BQP, see [command-line entry points](api/entrypoints.md).
For Python integration, start with the [runnable QUBO API example](api/index.md#runnable-qubo-example).
For custom callbacks, use the separate [SDP and heuristic template](CUSTOM_SDP_HEURISTIC.md#custom-solver-template).

## Development

BiqBin uses GNU Make for building and testing, Ruff for Python linting and formatting, and pytest-cov for coverage collection.

Common commands:

```bash
make                  # Incremental native build
make rebuild          # Force a complete rebuild
make test             # Full regression suite
make test-unit        # Focused unit tests
make coverage         # Full suite with Python coverage
make lint             # Ruff linting
make format-check     # Ruff formatting validation
```

GitHub Actions validates the project against Python 3.12 and 3.13, with MPICH and OpenMPI environments.

The canonical Python 3.12/MPICH job runs the complete regression suite and collects Python coverage reports.

## Building this documentation

Install the documentation dependencies:

```bash
python -m pip install -r requirements-docs.txt
```

Build the HTML site:

```bash
make docs
```

Preview locally:

```bash
make docs-serve
```

Generated HTML is written to `site/`.

The documentation build runs in strict mode: warnings cause a failure.

The Python API reference is generated by reading source files without importing the native MPI extension. Therefore, documentation can be built without a compiled solver, MPI, NumPy or SciPy.

To document new public Python interfaces, update their source docstrings and add the relevant objects to the appropriate `doc/api/` page.

## Documentation deployment

GitHub Actions currently validates documentation builds but does not publish or deploy the generated site.

Developers can build and preview the documentation locally using MkDocs.
